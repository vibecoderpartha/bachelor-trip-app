# Trusted Operation Register

No operation is implemented by this Draft. Every operation derives its actor
from a validated Auth session, revalidates the current Group relationship at
commit time, records an audit-safe result, and fails as a whole. A browser never
receives a service-role credential. “Narrow trusted boundary” describes a
reviewed server/database mechanism, not an implementation choice already made.

## Review conclusion

TOP-004 and TOP-005 remain separate: role transition and effective ownership
transfer have different valid inputs and continuity outcomes. TOP-006 combines
self-leave and Owner removal only because both produce the same membership
deactivation state; its authorization branches must remain separately tested.
TOP-012 is a trusted mutation, not a read path. No planned operation is an
authorization bypass or a general service-role proxy.
