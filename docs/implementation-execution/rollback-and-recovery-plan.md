# Rollback and Recovery Plan

All actions below are planning controls only. No Draft statement treats a
destructive data transform as trivially reversible. Where a rollback would
restore public/global/permissive authority, the only acceptable alternative is
a secured forward fix or continued containment.

| Layer | Trigger and authority | Rollback / containment action | Data guarantee and reversibility | Downtime expectation / evidence | Stop condition and forward-fix |
|---|---|---|---|---|---|
| 01 Local code change | Pre-release functional/security/design failure; implementation reviewer. | Revert the bounded code change or keep it unmerged. | No target data action assumed; reversible before deployment. | None expected; diff, build, test, and review record. | Stop if fallback exposes stale/unauthorised state; correct and retest. |
| 02 Packet boundary | Packet exit evidence fails; packet reviewers. | Hold the packet; revert only owned, reviewed changes. | Preserve prior accepted data/authority boundary; no dependent packet begins. | None expected; packet evidence and decision record. | Stop on an unsafe dependency; forward-fix only under the owning packet. |
| 03 Frontend release | Visual, Auth, or client-state regression; release authority. | Disable/revert the approved client release and clear stale Group/session state. | Client rollback must not reintroduce persona authority or global queries. | Deployment downtime is not established; release/smoke record. | Stop when old client is insecure; use a compatible secured forward fix. |
| 04 Schema migration | Constraint/index/schema defect; database/migration reviewer. | Use a reviewed down migration only before dependent data, otherwise apply a controlled forward migration. | Schema may be reversible only when no dependent data/policy state is lost. | Not established; migration log, schema version, constraint verification. | Stop for unplanned destructive change; forward repair with new evidence. |
| 05 Policy/RLS activation | Allow/deny mismatch or partial policy activation; security reviewer. | Keep target inaccessible or disable the affected secured path; correct policy and retest. | Never roll back to permissive RLS; policy rollback is not an access broadening. | Not established; two-Group matrix and policy version evidence. | Stop on any cross-Group success, inactive write, or removed access; secured forward correction only. |
| 06 Trusted operation | Partial write, replay, race, or audit mismatch; security/operation owner. | Abort transaction where possible; otherwise reconcile from idempotency/audit record. | A logical unit is all-or-nothing; compensation may be needed only for reviewed external side effects. | None to scoped downtime; correlation, result class, and reconciliation evidence. | Stop when transaction boundary cannot prove a complete safe outcome; narrow forward fix. |
| 07 Data transformation | Count/checksum/reconciliation failure; data/security reviewer. | Quarantine the affected logical unit, retain source and manifest, and retry only reviewed mapping. | Target data transform is generally irreversible; source/manifest preservation enables reconciliation, not data loss. | No cutover; manifest, checksum, exception, and retry evidence. | Stop for unknown mapping or silent repair; approve a forward transform after adjudication. |
| 08 Storage reconciliation | Object/metadata mismatch, public path, or failed removal; data/security reviewer. | Quarantine object/metadata pair, disable access, and reconcile through integrity evidence. | Do not delete the only object or metadata copy as a rollback shortcut; private target remains private. | Path-specific access interruption may occur; orphan report, checksum, and denial evidence. | Stop for public access or untracked orphan; controlled reconciliation only. |
| 09 Realtime disablement | Stale/unauthorised delivery or bad reconnect state; security/product reviewer. | Unsubscribe, clear cached Group data, and disable affected delivery until current authorization is re-established. | No payload authority is retained; delivery can resume only after reauthorization. | Feature degradation rather than broad downtime; subscription/denial logs. | Stop on cross-Group or removed-member event; fix authorization/resubscribe. |
| 10 Group migration / rehearsal | Claim, identity, finance, or configuration discrepancy; product/data/security reviewer. | Keep record unclaimed, inactive, or quarantined; preserve stable identity and source evidence. | No guessed authority, Owner promotion, finance rewrite, or configuration replacement. | Rehearsal/cutover blocked; exception/adjudication/recovery record. | Stop for conflicting proof or unproven recovery; reviewed retry or forward correction. |
| 11 Cutover and post-release containment | Smoke, isolation, recovery, reconciliation, or incident failure; separate cutover or operations authority. | Abort before routing if possible; otherwise contain unsafe paths, preserve evidence, and execute approved secured rollback/forward recovery. | Never restore PIN/persona, public Storage, permissive RLS, global query/realtime, or unreviewed legacy access. | Downtime is not established; S16–S19 outcome, monitoring, retention, and incident record. | Stop without an approved recovery path; remain contained until a secured decision is approved. |

The expected rollback authority, downtime, and evidence are explicitly
reviewed before their consuming Wave. Backup/recovery capability, retention,
and production deployment topology are external evidence inputs for W6/W7;
their absence does not block W1 documentation or IR-001 capability selection.
